# 菜单首帧观察场景

`menus.c` 是原生固件验证使用的独立入口，不参加游戏构建，也不包含固件。
它在固定灰色画面上依次调用真实的命令组、内政、外交、军事、武将表单、物品表单、粮食输入和城市详情控制器。

验证流程：

1. 用本仓库固定 SDK 和相同 MIPS 编译器编译场景，将游戏函数通过当前 ELF 符号地址链接。场景位于 `0x81c36000`，生产 BDA 保持原字节。进入等待画面后，发送一次独立确认按键。
2. 在菜单的第一个 `sango_text_draw_legacy` 入口暂停；武将、物品表单改在各自的 `sango_ui_draw_*_header` 入口暂停。这些入口均发生在外框绘制之后、内容绘制之前。
3. 诊断器通过 GDB 分段读取 C200 LCD 的 153600 字节 RGB565 数据；本场景此时应仍是完整的 `0x8410` 灰色背景。该地址只用于外部诊断，不在交付游戏中读取或写入屏幕指针。
4. 继续执行，截取完整页面，检查文字、字段和表格。用取消键进入下一个观察场景。`MARK[0]` 的奇数表示等待，偶数表示对应弹窗，最后为17；`MARK[1..8]` 保存控制器返回值。
5. 对修复前的精确 BDA 重复首个菜单观察。它在首个文字入口已经显示外框；继续后的菜单与修复后版本像素相同。

运行使用独立合成 NAND，并通过断点原字节装载 BDA、LIB、CLR，以隔离合成 NAND 的 ECC 差异。此验证针对 SDK 绘制和实际 LCD 中途可见性，不验证原生文件系统、真机耗时、垂直同步或完整战役。报告和截图位于 `validation/menu-atomic-firmware-validation.json`、`docs/screenshots/menu-atomic/`；本场景源文件哈希记录于报告中。
